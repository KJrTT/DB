# КТ-01 · Инвентаризация склада

## Для чего это делалось

В рамках контрольной точки необходимо было автоматизировать процесс сверки учетных остатков на складе с фактическим пересчетом (данные из файла `stocktake.json`). Скрипт выгружает данные пересчета в базу, находит расхождения (недостачи и излишки), обновляет учетные данные до фактических, помечает пустые полки как недоступные (`available: false`) и формирует журнал инвентаризации. 

## Как запустить (стандартный способ)

База данных MongoDB и Docker должны быть установлены. Все команды выполняются из корня репозитория (там, где находится файл `docker-compose.yml`).

1. Сбросьте базу данных до исходного состояния:  
    docker compose run --rm reset
    
2. Запустите скрипт инвентаризации:  
    docker compose run --rm python work/kt01/inventory.py
    
3. Запустите скрипт самопроверки, чтобы убедиться, что база данных изменилась правильно:  
    docker compose run --rm python kt01/check.py
    

## Особенности запуска в моей среде

Этот способ подходит для обычного пользователя. Однако у меня Docker и MongoDB развернуты на виртуальной машине, поэтому процесс подключения немного отличается:

- База данных развернута на виртуальной машине и доступна по IP (у меня статический: `192.168.0.222:27017`).
    
- Поднимаем контейнеры: `docker compose up -d`.
    
- Сбрасываем базу: `docker compose run --rm reset`.
    
- Перед запуском скриптов убеждаемся в наличии связи с ВМ с помощью команды `ping 192.168.0.222`.
    
- Так как база находится на другой машине, при запуске скриптов мы явно передаем IP-адрес через переменную окружения `MONGO_URI`.
