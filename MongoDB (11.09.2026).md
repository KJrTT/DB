**Документ** --> базовая единица хранения данных в MongoDB. Что-то по-типу аналога строки в релиционной БД (SQL/posgres), однако хранится в виде BSON (бинарный JSON). 

Имеет гибкую схему, то есть в одной коллекции могут иметь разных набор полей. (При инсерте необязательно добавлять все данные). При этом состоит из пар "Ключ-значение" (словарик). 

Всегда имеет поле "Id", которые уникально идентифицирует документ внутри коллекции. Если его не указать, то БД сгенерирует автоматом.

**Коллеция** --> группа документов (таблица в SQL). Отлчия:
- Не требует предварительного описания схемы
- Документы внутри коллекции логически однородны, но структурно могут отличаться
- Создаётся автоматически при первой вставке документа
- Поддерживает идексы (составние, уникальные и тд)

### Иерархия "База данных -> Коллекция -> Документ -> Поле"

## BSON

**Binary JSON** --> бинарный формат сериализации данных или же надмножество JSON. 

Произвдительность BSON намного выше, тк хранит длины строк и вложенных объектов в начале структуры, что позволяет быстро перескакивать через поля при поиске, не парся весь документ.

Добавляет новые типы данных:
- ObjectID
- Date
- Binary (произвольные байты)
- Decimal128
- Regex
- JS

**Документа BSON**
```cmd
  <размер (4 байта)> <элементы> <нулевой байт>
```
**Как выглядит каждый элемент**
```cmd
  <тип (1 байт)> <имя поля (cstring)> <значение>
```

Важные моменты:
- Чаще всего BSON больше по размеру из-за метаданных
- Одной и тоже значение может быть представлено разными типами (int32/double и тд)

## Некоторые моменты

**Обычное (скалярное) поле** --> поле, значением которого является простое значение: строка, число, boolean, дата, ObjectId и т.п.

**Пример** : 
```json
 {
  "name": "Иван",
  "age": 30,
  "active": true
}
```

**Вложенный документ** --> значение поля — другой документ (объект). Используется для моделирования связей «один-к-одному» и «один-ко-многим», когда данные логично хранить вместе.

**Пример** :

```json
{
  "name": "Иван",
  "address": {
    "city": "Москва",
    "street": "Тверская",
    "zip": "101000"
  }
}
```

**Особенности** : 
- Вложенность может быть любой глубины (до 100 уровней)
- При поиске по вложенному объекту целиком важен порядок полей

**Массив** --> значение поля — упорядоченный список значений. Элементами могут быть скаляры, документы или другие массивы.

**Пример**

```json
{
  "name": "Иван",
  "hobbies": ["футбол", "шахматы", "чтение"],
  "orders": [
    { "id": 1, "sum": 100 },
    { "id": 2, "sum": 250 }
  ]
}
```
